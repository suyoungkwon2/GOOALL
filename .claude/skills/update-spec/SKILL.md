# 스펙 관리 절차

스펙은 `docs/specs/Fxx-*.md`, 인덱스는 `docs/specs/README.md`. 양식은 `_TEMPLATE.md`.

## A. 새 기능
1. 다음 번호로 `Fxx-이름.md`를 `_TEMPLATE.md`에서 복사해 작성 (상태 Draft)
2. 요구사항은 ID(Fxx-R1…)와 우선순위(Must/Should/Could)를 붙이고, 수용 기준은 "검증 가능한 문장"으로
3. 모르는 건 지어내지 말고 "열린 질문"에 적는다
4. README.md 인덱스 표에 행 추가
5. 사용자에게 열린 질문을 정리해 묻는다. 답을 받으면 반영하고 상태를 Ready로

## B. 구현 후 갱신 (동작이 바뀐 코드 변경 직후 반드시)
1. 변경한 코드가 어느 스펙(들)에 해당하는지 찾는다
2. 스펙과 실제 동작을 비교:
   - 스펙이 틀렸으면 → 스펙 수정
   - 코드가 스펙을 어겼으면 → 사용자에게 알리고 어느 쪽이 맞는지 묻는다 (임의로 한쪽을 고치지 않는다)
3. 스펙 맨 아래 **변경 이력**에 `- YYYY-MM-DD: 무엇이 왜 바뀌었는지 한 줄`
4. 수용 기준을 통과했으면 체크박스 체크, 전부 통과하면 상태를 Built로 (README 인덱스도 같이)
5. 구현 후 스펙이 바뀐 경우 상태를 Changed로 두고 코드 수정 작업을 PROGRESS.md에 추가

## C. 불일치 점검 (qa가 마일스톤 끝에 실행)
각 스펙의 요구사항 ID마다 구현 위치(파일:심볼)를 찾아 표로 보고:
| 요구사항 | 구현됨? | 위치 | 비고 |
미구현·초과 구현·스펙 외 동작을 구분해서 보고한다.

## 금지
- 스펙에 없는 기능을 조용히 추가하지 않는다 (필요하면 A부터)
- PRD.md에 동작 규칙을 복사하지 않는다 (링크만)
- 요구사항 ID 재사용 금지
